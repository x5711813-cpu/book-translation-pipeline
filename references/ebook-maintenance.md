# 电子书校对、目录生成与格式重排

适用于已有 EPUB、中文书稿，或翻译流程完成后的出版整理。三项功能可单独或组合执行。仅校对、修目录或排版时，不启动翻译、OCR、20页试译或模型服务；不要求创建翻译项目。需要核对扫描原文时才进入 OCR 流程。

## 工作范围与留档

- 首先识别 EPUB 2/3、可重排/固定版式、原有目录、spine 阅读顺序、语言、封面、注释、图表、字体与媒体。以 spine 为序，不能按 ZIP 文件名排序。
- 默认交付与输入同格式的新文件，保留原件。PDF/扫描件先提取或 OCR 成语义书稿，再出版；只在用户要求转换时改变格式。MOBI/AZW 等依赖已安装且获准的转换工具，不声称直接支持。
- 在独立工作目录保存输入哈希、问题清单、目录结构、排版 CSS、修订记录、输出哈希和验证报告。有既存翻译项目时复用中间稿与修复记录。
- 校对缺少原文时可以完成文字、结构和一致性检查，但将忠实度、疑似漏译、引文与数字准确性标为“未核实”；不得凭通顺程度补造原意。

## 1. 电子书校对

先读 [publication-proofreading.md](publication-proofreading.md)。分三层执行，报告不得把程序检查等同于全文审校：

1. **结构与文件**：包结构、阅读顺序、缺失资源、目录锚点、重复 ID、注释跳转、乱码和空章节。使用 `scripts/ebook_tool.py audit` 做基础检查；它不校验全部 EPUB 规范、CSS url()、脚本或复杂媒体链接。
2. **文字与原文对照**：全文按章节审读，检查错别字、漏字/重字、OCR 混淆、跨块断句、术语/译名、标点与引号、数字/单位、引用与注释。Markdown 使用 `audit_manuscript.py` 产生候选；EPUB 保留 XHTML 元素与来源定位，不能把整包粗暴转成纯文本再覆盖。模型按已有授权与配置使用；没有模型服务也可由当前执行者审校。
3. **渲染**：常规正文与所有特殊版式抽检，点击目录和注释往返，记录阅读器、视口和结果。结构通过不代表视觉通过。

问题记录至少包含 `id, file, locator, category, severity, before, proposed_after, evidence, status`，其中 locator 是 XHTML ID/稳定节点路径或稿件行号；状态为 pending/accepted/rejected/unverified。应用修订前精确匹配 `before` 和输入修订，防止过期位置覆盖新内容。分离文字修订与排版改动，保留可回放记录。确定的笔误可修复，语义不明项保留并说明依据；不要全局替换标点、人名、数字或断行。

## 2. 生成或重建目录

以正文标题、原书结构、既存目录与 spine 交叉核实层级。目录条目保存标题、层级、文件与定位；无标题的章节可暂用文档 title，但须审阅。不能仅因字号大、居中或出现“第…章”就把正文句子提升为标题。

```powershell
python scripts/ebook_tool.py outline input.epub --output work/outline.json
python scripts/ebook_tool.py rewrite input.epub --toc work/outline.json --output work/with-toc.epub
```

`outline.json` 含输入 SHA-256 与有序 `entries`，每项包含 `label, level, file, heading_index`（文档内所有 h1–h6 的零基序号；没有标题时为 null）。已有 `anchor` 仅供定位核查。审阅后可改 label/level、删除不应入目录的条目；同级可以重名，不得按标题文本去重。索引必须仍对应同一输入。不能使用同一个定位重复入目录。脚本检查输入哈希，保留已有锚点，仅为缺少 ID 的目标补稳定 ID；跨章不依赖标题拼音生成唯一性。

- 默认纳入有实质内容的序言、篇/章/节、附录、参考文献与索引；不把图注、页眉、每条注释当作章节。不创建空层级；标题跳级需核实后调整。
- EPUB 3 维护 `nav.xhtml` 的嵌套目录；已有 NCX 同步更新。EPUB 2 保持其版本并生成/更新 NCX，不静默升级。
- 保留原有 landmarks、page-list 与它们的目标；纸书页码与章节编号不同，不能为了去页码删除合法章号或年份。没有可靠页面映射时不编造 page-list。
- 生成供阅读器侧栏使用的逻辑目录；如果用户要求正文中可翻页看到的目录，再将导航页按确认的书籍结构加入 spine。脚本不擅自增加这个阅读位置。
- 独立确认目录顺序与 spine、层级、可见标题一致，并逐项验证跳转。默认全 h1–h6 提取仅是候选，不是已确认书籍结构。

`outline` 输出 `CANDIDATES_REQUIRE_REVIEW` 与定位明确的 `warnings`：代码注释疑似标题、同文件多个一级标题、编号深度或父编号异常。警告不自动删除正文或改变目录；篇/章层级偏移、多章合文件等合法情况须结合原书裁决。没有警告也不等于语义验收通过。

- Markdown 的 `#` 可能来自代码注释，`原文 → # 译文` 等翻译工作备注不得直接作为书名级标题。先把误解析的正文恢复为段落/代码，再生成目录。
- 核对完整章标题与分开的“第 N 章”“章名”是否重复；只合并同一位置经来源确认的重复，不能全书按相同文本去重。
- 对已确认的章编号体系，`N.M.K` 应位于 `N.M` 下，不能只检查 level 数值或链接是否存在。附录字母编号、前言、注释、习题等按原书结构保留；不要强行编号。
- 正文标题修复后，从同一份审定 outline 重建 EPUB nav/NCX 或 PDF 印刷目录/书签，并再次读取成品验证实际父子关系。PDF 细则见 [pdf-publication.md](pdf-publication.md)。

## 3. 格式重排

先纠正语义结构，再调整 CSS。对普通可重排中文书，使用相对字号、适度行距与首行缩进；对诗歌、代码、列表、表格、注释、题记、图注、居中行使用独立样式，不能把所有 `<p>` 当正文。保留强调、超链接、语言/方向、无障碍语义与段落边界。

```powershell
python scripts/ebook_tool.py rewrite input.epub --css work/reflow.css --output work/reflowed.epub
# 可在同一次 rewrite 中同时传入 --toc 和 --css
```

以 `assets/epub-template/reflow.css` 为起点复制到项目，再按实际类名和选定体例修改。该样式作为独立覆盖层追加，保留原 CSS 和内联样式；强选择器或内联样式可能优先，须渲染后定点调整。不要用全局 `!important` 强行清洗。脚本不自动删除硬换行、合并段落、重建表格、拆章或将绝对定位扫描页转换为流式正文。

- 正文缩进用 CSS，不插入全角空格；图片按可用宽度缩放，不拉伸；表格需保留表头、单位与完整列，窄屏查看避免截字。
- 不强制字体、背景色、固定字号或不可调整的屏幕尺寸；检查放大字号及阅读器深色模式。
- 固定版式转换需先恢复文本与阅读顺序。不能只改 `rendition:layout` 就宣称转换成功；脚本拒绝对含固定版式的书套用流式 CSS。
- 排版和目录任务中，章节正文文本、注释、原始资源与阅读顺序必须保持。删除/合并/新增章节或改变内容的操作需要项目内记录，不能悄悄附带进行。

## 4. 验收与交付

```powershell
python scripts/ebook_tool.py audit work/final.epub --output work/epub-audit.json
```

改写工具始终写新文件，不覆盖已有输出；结构错误产生非零退出码并保留报告。`rewrite` 比较正文 body 的文本序列与全部非编辑资源字节，在生成导航/补锚点/添加 CSS 时防止文字丢失，输出输入及输出哈希和变更文件清单。它只表示 **基础结构检查**，不能作为出版 PASS。

如有已安装的 EPUBCheck，运行它并保留结果；如不可用，明确标“未执行 EPUBCheck”，不要下载或伪造通过。最终交付还需要检查锚点覆盖之外的注释语义/回链、CSS 引用、封面、表格、字体与代表页面。至少使用窄屏与宽屏、默认与放大字号抽检；无可用渲染器时保留“视觉检查未执行”，不能称最终出版就绪。

交付最终书、可编辑目录/样式或修订稿、问题裁决及验证报告。校对任务说明全文审读范围和未核实项；仅目录/排版任务将翻译/OCR/内容审校门槛标为不适用，同时执行 [quality-gates.md](quality-gates.md) 中适用的结构与 EPUB 检查。

规范依据：[W3C EPUB 3.3](https://www.w3.org/TR/epub-33/)（导航、spine、包文档与布局）。
