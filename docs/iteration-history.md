# 迭代历史与设计取舍

## 第一阶段：把整书翻译变成可恢复流水线（2026-08-21）

早期目标不是单次生成译文，而是让长达数百页的任务可以暂停、恢复、复查和重新构建。由此形成以下约束：

- 物理页不是语义段落；翻译前必须跨页重建段落。
- 每个语义块保留稳定 ID、源页范围和内容哈希。
- OCR、翻译、终审与构建结果分别缓存，EPUB 排版调整不得触发重新翻译。
- 模型只处理明确的目标块，并携带必要的邻接上下文。
- 终审与修订有上限；不能用无限循环掩盖 unresolved 状态。

这一阶段产生了初始化、源检查、OCR、区块重建、翻译、图表和 EPUB 构建等通用脚本。

## 第二阶段：真实历史著作暴露出版级缺陷（2026-08-22 至 2026-08-24）

《中世纪的西方社会与教会》项目暴露出“译完且能生成 EPUB”仍远未达到可交付标准。集中出现的问题包括：

- OCR 页码、脚注号和行号混入正文，数字需要结合上下文判断。
- 跨页残句、错误拆段、段落重复和章节分节编号不一致。
- 直接引语缺失引号、嵌套引号错误、句号与注释角标位置异常。
- 分号、逗号和省略号相邻，段首或段末遗留不可能出现的标点。
- 原始 HTML 标记、替换字符、未翻译英文和局部乱码进入成书。
- 教宗名录、索引、注释和普通正文需要不同的结构恢复策略。
- 首行缩进不能仅由段落文本决定，还取决于标题、引文、列表等前置版式。

这些问题被提炼为通用检查规则和质量门槛；包含固定书名、固定文件名或特定页码的修复脚本仍留在项目目录，不进入技能默认规则。

## 第三阶段：从“命中即失败”改为分级诊断（2026-08-24）

中文分号、数字、引号和句末形式常常需要语境判断。把全部正则命中设为失败会诱导机械修改，因此检查器采用三级结果：

- `error`：高置信度结构错误，如缺失注释定义、正文裸露标记或句末注释角标位于标点之前。
- `warning`：需要联系上下文的语言或结构候选，如分号、数字、重复片段和未闭合引号。
- `style`：不一定影响正确性的体例候选，如中文语境中的半角标点。

普通模式只由 `error` 阻断；`--strict` 用于最终清单复核。Markdown 中的 frontmatter、代码、URL 和链接目标被屏蔽，避免检查器破坏技术性内容。该架构概念上参考 Tech-Doc-Style-Chinese，但保留中文译著自己的引号、注释和排版规范。

## 当前边界

- 正则检查器负责发现候选，不负责自动改写所有候选。
- 模型审校输出必须经过原文子串、结构和事实约束验证后才能应用。
- 项目特例应进入项目配置或 repair 文件，只有在多本书中成立的规则才提升为技能默认值。
- 本仓库不保存受版权保护的源书、完整译文或项目缓存。
